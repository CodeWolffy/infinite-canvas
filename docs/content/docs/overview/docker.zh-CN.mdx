# Docker 部署

内部平台通过 Docker Compose 部署为 Web、API、PostgreSQL 和 MinIO 四个服务。默认
Compose 只对外映射 Web 的 `3000` 端口，浏览器通过 Web 容器的 `/api` 反向代理访问
API。

<Callout type="warn">
默认配置使用 HTTP，只适合可信局域网。不要把这套部署直接映射到公网；如需扩大访问边界，
应先配置并验证 HTTPS 反向代理与相应的网络安全策略。
</Callout>

## 准备环境变量

克隆仓库后复制环境变量模板，并在启动前替换所有 `change-me` 值：

```bash
git clone git@github.com:basketikun/infinite-canvas.git
cd infinite-canvas
cp .env.example .env
```

必须妥善设置的部署密钥包括：

- `POSTGRES_PASSWORD`，并同步修改 `DATABASE_URL` 中的数据库密码；
- `MINIO_ROOT_PASSWORD` 和 `MINIO_SECRET_KEY`；
- 至少 32 个字符的 `CHANNEL_ENCRYPTION_KEY`，用于加密 PostgreSQL 中保存的渠道
  API Key；
- `BOOTSTRAP_ADMIN_PASSWORD`，首次创建管理员时使用。

标准 Compose 通过 Web 容器的同源 `/api` 反向代理访问 API，不需要把会变化的内网
IPv4 写进配置；局域网设备直接使用运行主机当前地址访问
`http://<局域网-IP>:3000` 即可。只有在 API 被单独跨域访问时，才将 `CORS_ORIGIN`
设置为稳定的 Web 来源（可用逗号分隔多个来源）。`COOKIE_SECURE=false` 只应保留在可信
局域网 HTTP 场景。
不要把填写完成的 `.env` 提交到仓库。

## 启动内部平台

从当前源码构建并启动四个服务：

```bash
docker compose up -d --build
```

| 服务 | 用途 | 对外端口 |
| --- | --- | --- |
| `app` | Vite Web 应用与 Nginx 反向代理 | `3000` |
| `api` | 认证、存储、生成队列与管理后台 API | 无 |
| `postgres` | 账号、画布、素材、任务、消息与配置 | 无 |
| `minio` | 用户上传及生成的图片对象 | 无 |

本机访问：

```text
http://localhost:3000
```

同一局域网的其他设备访问：

```text
http://<局域网-IP>:3000
```

如果运行主机通过 DHCP 获取地址，地址变化后使用新的 IPv4 访问即可；服务端数据保存在
PostgreSQL 和 MinIO 卷中，不会因地址变化丢失。由于浏览器会把新的 IP 视为新的站点，
已有登录 Cookie 不会迁移，用户需要在新地址重新登录。更稳定的做法是在路由器中为运行
主机设置 DHCP 地址保留，或为它配置局域网 DNS / mDNS 主机名，再使用固定主机名访问。

如果主机启用了防火墙，只允许可信局域网访问 TCP `3000`。不要对外映射 API
`3001`、PostgreSQL `5432`、MinIO `9000` 或 MinIO 控制台 `9001`。

## 本地构建镜像

`docker-compose.yml` 已经会从当前检出的源码构建 Web 和 API 镜像。如果需要显式使用
本地镜像标签，也可以运行：

```bash
docker compose -f docker-compose.local.yml up -d --build
```

## 导入 1Panel

1. 将仓库上传或克隆到服务器，并按上文在 `docker-compose.yml` 同目录创建 `.env`。
2. 在 1Panel 中新建 Compose 编排，导入仓库内的 `docker-compose.yml`，并将仓库目录
   作为构建上下文。
3. 确认只有 `3000:3000` 对外映射后，构建并启动编排。
4. 在服务器和上游防火墙中，将 `3000` 端口限制为仅可信局域网可访问。

不同 1Panel 版本的界面名称可能不同。本仓库提供 Compose 定义，但不代表所有 1Panel
版本、主机和网络环境均已完成生产验证。

## 数据与备份

PostgreSQL 和 MinIO 都是权威持久化数据源。Compose 分别使用 `postgres_data` 和
`minio_data` 数据卷保存数据，浏览器本地存储不能代替服务端备份。

应配置一个每日备份任务，在同一恢复点备份 PostgreSQL 与 MinIO；可以使用短暂停写维护
窗口，或采用协调一致的快照/导出流程。保留最近 7 个每日恢复点。只备份数据库或只备份
对象存储，恢复后都可能造成媒体引用与实际文件不一致。

请将 `CHANNEL_ENCRYPTION_KEY` 单独备份到访问受控的密钥存储或离线介质。恢复数据库时
如果没有使用完全相同的密钥，已有渠道 API Key 将无法解密。当前 Compose 只负责创建
持久化数据卷，不会自动调度或验证备份；请在自己的环境中实际演练恢复流程。

## 文档站镜像

文档站位于 `docs/` 目录，按带服务端能力的 Next.js standalone 应用单独构建，不打进主应用镜像。

使用发布镜像：

```bash
cd docs
docker compose up -d
```

基于当前源码本地构建：

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

## 统计分析（可选）

项目**默认不接入任何统计**：不设置下列环境变量时，页面不会加载任何统计脚本，也不会发送任何外部请求。你在自己的部署上想查看流量时，设置对应环境变量即可，无需修改代码或重新构建镜像——镜像启动时会据此生成运行期配置。

统计按「每家一个独立变量」配置：**填了谁就启用谁，可同时启用多家**（例如 GA4 + 百度一起开）。仅支持 GA4 与百度，两者都只接受 ID，脚本地址由代码固定拼接，不接受任意脚本地址或内联 JS。

| 变量 | 说明 |
| --- | --- |
| `ANALYTICS_GA4_ID` | Google Analytics 4 衡量 ID（`G-XXXX`） |
| `ANALYTICS_BAIDU_ID` | 百度统计站点 ID（`hm.js?` 后面那串 hash） |

在 `docker-compose.yml` 的 `environment` 中配置（文件内已附注释示例），下例同时启用 GA4 与百度：

```yaml
services:
  app:
    environment:
      ANALYTICS_GA4_ID: G-XXXXXXXXXX
      ANALYTICS_BAIDU_ID: e8263761cc5c32f5f7a855b8203b965a
```

单页应用的路由切换会自动向所有已启用的统计上报 pageview。

<Callout type="warn">
请只在你自己的站点上配置统计 ID，不要把 ID 提交进仓库；fork 或自托管本项目的用户默认不会产生任何统计。
</Callout>
