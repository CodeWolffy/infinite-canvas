# Pending Tests

The current release needs manual verification in these areas:

- Internal platform accounts and permissions: bootstrap an administrator, create users, require a password change on first login, disable users, and reset passwords. Disabling or resetting must revoke existing sessions. Regular users must not enter `/admin` or read channel names, base URLs, API keys, priorities, weights, or image prices from model pickers or APIs.
- Internal platform cross-device data: the same account on two LAN devices should see the same canvas projects, nodes, connections, viewport, assistant messages, private/public assets, image batches, and text results. Canvas edits should save serially after the debounce and recover from refreshes or temporary failures without an older response overwriting a newer snapshot; simultaneous editing intentionally remains last-write-wins.
- Internal platform asset permissions: every user may publish public assets; creators may edit or delete their own entries, administrators may manage all public assets, and other users may only use them. Removing a public entry must not break images already referenced by another user's canvas or private asset, and private data must not be readable across users.
- Internal platform file storage: canvas uploads, drag-and-drop, assets, and text attachments should accept only PNG, JPEG, and WebP. User images over 20 MB and generated results over 50 MB or with unsupported formats must fail; successful uploads and generations should record dimensions and reload from protected MinIO media URLs rather than using browser base64 as authoritative storage.
- Internal platform image jobs: one multi-image action should create one batch containing independent queued tasks with recoverable queued, running, succeeded, and failed states. Jobs must continue after closing or refreshing the page; the canvas Stop action should explicitly stop only local waiting while the server continues processing and billing, then restore results automatically. Retrying a failed canvas slot should requeue its original task without creating another batch; completed non-running batches must be deletable, all history pages must load, and referenced media must remain in MinIO.
- Internal platform image-job recovery: after refresh or stopping local waiting, image children with persisted server batch markers and their configuration parent must retain accurate queued, running, succeeded, and failed states.
- Internal platform routing: strict primary/backup priorities, weighted routing within the same priority, controlled failover for network errors, timeouts, 429, 5xx, 401, and 403, no failover for user input or moderation errors, and at most one extra route for ambiguous errors. Both the global image concurrency limit and each channel concurrency limit should apply.
- Internal platform text flow: canvas text generation and image questions should use only published administrator-managed text models. Nodes should persist and reuse a server `conversationId` and use `textRequestId` to associate the current request exactly; messages, model, actual channel, state, and duration should persist with canvas ownership. Current PNG/JPEG/WebP attachments should reach OpenAI or Gemini without being attached again to history. Reusing the same request ID must not create duplicate conversations, messages, or attachment references; concurrent multi-text generation should settle each child independently, refresh or stopping local waiting should recover the current request and its parent configuration state, and API restarts should mark interrupted text requests failed instead of leaving them running forever.
- Internal platform administration and analytics: administrators should manage public models, channels, upstream mappings, priority, weight, timeout, channel concurrency, and per-image RMB prices, and fetch compatible model lists. Analytics should provide today, 7-day, 30-day, and custom ranges; filters by user, model, and actual channel; image counts, costs, duration percentiles, both success rates, text-call counts, and the live image queue. Filtering by actual channel must still count that channel's failed and failover attempts. Channel rows should show the latest attempt status, duration, upstream model, and error summary. Public assets should support filtering, search, editing, and deletion.
- Internal platform usage analytics fix: after another user successfully generates images, analytics should show the corresponding requests, successful images, cost, and user/model/channel breakdowns. Re-entering or focusing the page should fetch current data, and its horizontal padding should match the other administration pages.
- Internal platform usage analytics layout: on desktop, the 10 metric cards should use five cards per row across two compact rows with noticeably reduced card height; narrow screens should remain readable and responsive.
- Internal platform administration layout: on desktop widths, the model and channel management content should use the available main-column width without excessive outer whitespace; tables, actions, drawers, and dialogs should remain usable at narrow widths.
- Internal platform model setup: the channel table should keep base URLs compact, and administrators should be able to fetch and search upstream models, then create a public model or bind an existing one with capability, price, publication status, priority, weight, and enabled state in one flow.
- Internal platform model variants: two published models with different display names and prices should be saveable even when both bind to the same upstream identifier (for example, `gpt-image-2`); the user model picker must keep both variants selectable independently.
- Internal platform model deletion: deleting a model should hide it from admin and user model lists, remove its channel bindings, and preserve historical generation/text/statistics records; the deleted model must not become selectable again.
- Gemini image channels: after configuring a Gemini `generateContent` relay such as `https://torchai.ai/v1beta`, generation requests should include the API key as `?key=`, use `generationConfig.imageConfig` with `responseModalities`, and return an image for the relay's Nano Banana model instead of being rejected because of the unsupported `responseFormat` field.
- Local Agent restoration: authenticated user pages should expose the resizable Agent panel from the top navigation, canvas pages should show the Agent button and compact connection state, and an existing local token should reconnect silently. Agent URL, token, Codex model, skills, history, logs, and canvas operations must remain browser/local-Agent concerns and must not be stored in platform channel configuration; administration pages should not mount the Agent panel.
- Internal platform deployment and recovery: Docker Compose should start Web, API, PostgreSQL, and MinIO while exposing only Web port 3000 to the LAN. Login, cookies, reverse proxying, and health checks should work through a LAN IP and 1Panel; plain HTTP is limited to a trusted LAN. PostgreSQL and MinIO must be backed up and restored as one recovery point, while the channel-encryption master key needs a separate backup and must not appear in logs.
- Internal platform image-editing focus: normal reference-image editing should continue to work. Mask editing currently sends the mask as an additional upstream reference, so each target channel needs explicit manual verification for expected mask semantics, output quality, and error handling.

- Canvas navigation: the canvas should open in Move mode by default, and the bottom toolbar should switch between Select and Move modes and reflect the active mode with its icon; Select should draw a clearly spaced dashed range whose dash length, gap, and stroke width remain visually constant at every zoom level, while Move should drag elements directly and pan only when dragging the blank background. Clicking blank canvas space in either mode should deselect the current node and close its top toolbar and lower prompt panel. Holding Control or Space should temporarily invert the active tool without changing the toolbar mode: Select becomes Move, and Move becomes range selection. After clicking any canvas-page button, pressing Space should only invert the tool and must not trigger that button again. Middle-button panning from any position and additive node selection with Shift/Cmd should continue to work, while Space remains available inside text inputs and editable content.
- English and Simplified Chinese switching across navigation, settings, titles, descriptions, Ant Design components, and persisted preferences.
- Global Dropdown, Menu, Select, Cascader, and TreeSelect popup backgrounds, hover states, and selected states in both light and dark themes.
- Canvas node resize stability: importing an image should open its prompt panel, resizing it immediately from any corner should temporarily hide the panel, remain smooth without flashing or triggering a maximum update depth error, and restore the panel after release. Prompt scrolling, generated-prompt restoration, edit-prompt persistence after closing an existing image or text node panel, expanded prompt editing with live synchronization and `@` references, image editing, drag-and-drop references, and generation configuration should continue to work.
- Text output count: both a text node's lower prompt panel and a generation configuration node in Text mode should expose an independent generation count from 1 to 15, default to one, and create that many text nodes. Changing the text count must not alter the image count, and switching a generation configuration node back to Image should continue to use the configured image count.
- Node editing entry points: the image toolbar should default to icons without labels and no longer include Edit; the text toolbar should no longer include Edit or Edit text. Clicking an image, text, or video node without dragging should open its lower prompt panel directly, while image toolbar labels can still be enabled explicitly from the toolbar settings.
- Canvas side panel: clicking an element row should smoothly center and select its node without zooming above 100%; image elements with content should still open the large preview without triggering canvas focus.
- Multi-image canvas generation: starting N images should immediately create one image node with N expandable slots and one incoming connection; each empty slot should independently show generating or failure while requests are running, every slot with image content should always display that image, and the first successful image should appear as the primary image immediately. The collapsed state should use a compact stack with at most three closely spaced backplates and a clearly legible count control; only clicking the count control should expand or collapse the slots upward and to the right, while double-clicking the image should open its large preview. Every completed secondary image should keep a clearly legible primary-image action visible in both themes. Expanded groups should remain expanded when clicking elsewhere, dragging, resizing, or previewing, and multiple groups may remain expanded together.
- Multi-image primary selection: choosing another primary image should preserve the node center and current maximum edge while adapting to the new image ratio; free-resize nodes should keep their exact dimensions, and the viewport zoom indicator must not change.
- Failed multi-image slots: every failed slot, including the current primary slot, should expose retry and delete actions. Retry should update only that slot without replacing an existing successful primary image; delete should remove only that failed slot and update the displayed count.
- Multi-image resize: resizing the root node while child images are expanded should keep the group expanded and resize normally without triggering nested React updates or an application error.
- Multi-image alternatives: expanded images should use up to four columns so larger batches stay compact; double-clicking any completed child image should preview that exact image without changing the primary image. Every completed image, including the primary image, should provide an independent download action, while alternatives should also keep clearly legible create-copy and set-primary actions in both themes. Create-copy should add an independent image node to the right of the group, select it, and leave the original image group unchanged.
- Canvas Agent startup, MCP status, model and permission controls, approvals, version reporting, diagnostics, streaming responses, history consistency, multi-tab isolation, and local Skill management.
- Agent header tabs in English and Chinese at different panel widths; labels should collapse to icons and counts before either edge is clipped.
- Agent message layout, Markdown, code blocks, attachments, token statistics, progress timelines, command groups, and scroll-follow behavior.
- Agent inline references: type `/` to select an enabled Skill or `@` to select a canvas asset at the caret; tokens should remain aligned with text, support keyboard navigation and hover previews, and preserve their positions after sending or refreshing.
- Agent message metadata: image attachments, Skills, canvas references, and local previews should survive page refreshes and Agent restarts through exact `clientMessageId`, `threadId`, and `turnId` ownership; protocol upgrades must not reset the independent storage format, unknown or damaged storage must refuse writes without overwriting files, no records may be silently pruned by count or size, and deleting a thread should remove its metadata and preview assets without relying on browser IndexedDB or text matching.
- Prompt Center layout, source synchronization, search, asset insertion, prompt detail dialogs, and compact split-layout prompt pickers in the image and video workbenches.
- Workbench history image cleanup: after generating content in the image or video workbench, deleting an asset, canvas image node, canvas content, or canvas project must not remove thumbnails, results, or references from generation history; deleting a generation record should still remove its dedicated local files.
- Settings import/export and WebDAV-related configuration.
- Local storage settings: the Settings page should provide a Local storage tab that reads only the `infinite-canvas` database and shows IndexedDB usage, total site usage, browser quota, quota percentage, and per-object-store record counts and content size; refreshing after local data changes should update the figures without blocking the rest of the page.
